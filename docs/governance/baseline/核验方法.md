# FL-BASE-001 核验方法

以下为只读复核说明，不要求在原受保护工作区运行任何写入命令。

1. SHA-256：在本目录使用Python hashlib.sha256或已核验的shasum读取SHA256SUMS，逐文件比较；清单自身以PR/HANDOFF的SHA比较。清单不含自身。
2. 原文：读取sources下UTF-8字节，确认活跃基线与门禁5原文作为连续完整区块出现在归档版；历史追加原文在日志中完整出现且位于本工单记录之前。保留三个已归档标记。
3. Git：使用git --no-optional-locks，关闭diff.autoRefreshIndex。读取基点6c1473b93cb3d2ad122cf974a6c843950a0f4da6的ls-tree，按Git blob字节算法比较已跟踪文件；不得运行write-tree、恢复index、prune、GC或验证引用写入。
4. 现有交付：按119文件索引核对原路径和SHA；偏差接受原文SHA应为ea398d975dd22d3c491528c8baf8c5de1020a620f56ab6b332e4472636b1e00b。原FAIL及V1不可修改。
5. PR：通过GitHub只读元数据取得目标dev、完整HEAD、状态与文件列表。差异必须全部为docs/governance/baseline/新增文件；以CI run.head_sha核对该HEAD。
6. 回滚：读取逆向numstat确认只撤销授权新增文档；不实际应用差异。实际回滚另开工单并保留审计历史。
7. 敏感扫描：见自测报告中的六类格式、高熵阈值、按来源验证的豁免与内存正反例要求。任何真实命中仅输出位置和类型，不打印其值。

本地核验程序仅在隔离执行目录运行；不修改业务测试或CI。BASE-T01～T12原始结果与最终交付清单一同保留在本机HANDOFF包。
