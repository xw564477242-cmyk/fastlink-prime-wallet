# 状态模型与继承规范 v1（PENDING）

| 正式状态类别 | 定义 | 准入与退出 | 责任 |
|---|---|---|---|
| VERIFIED | 在明确环境、版本、输入和范围内已验收的成果 | 完整证据且相应门禁通过；输入变化转STALE | 总控确认验收；执行端保留证据 |
| PENDING | 成果已产生但尚未通过相应验收门禁 | produced事件产生；补齐证据和验收批准后才能VERIFIED | 执行端提交，总控评审 |
| STALE | 输入、适用范围或证据有效性改变，旧结论不能直接复用 | 标明变化来源及最小影响范围；定向复验形成新成果并经门禁验收 | 执行端提出复验，总控批准 |
| PERMANENT-DEVIATION | 已接受但不能追溯消除的永久偏差 | 不因复验成功移除；任何调整须独立治理决策并保留旧记录 | 项目所有者接受，总控继承 |
| HISTORY-GAP | 原始历史记录缺失或尚未归档 | 取得真实原文且经审查后仅追加“已补充”记录；旧缺口历史保留 | 原文责任人提供，总控审查 |

实现：前三类为result.status；后两类作为正式状态类别出现在constraints中。DEV1-T03、DEV1-T12、EVIDENCE-RETENTION携带PERMANENT-DEVIATION；EARLY-HISTORY携带HISTORY-GAP。不得用VERIFIED覆盖约束。尚未开始使用execution_phase=not_started、status=null，不能混为PENDING。

## 转换

not_started → 成果实际产生 → PENDING → 证据完整且相应验收门禁批准 → VERIFIED。

VERIFIED/PENDING → 输入变化 → STALE → 形成定向复验新成果 → PENDING → 门禁验收 → VERIFIED。允许已有STALE成果携完整复验证据及批准转VERIFIED，审批链不得跳过。任何普通转换必须原样携带约束列表。

## 可复用判定

必须同时满足：结果VERIFIED；输入指纹一致；适用环境和范围一致；证据可读；无到期未回补豁免。约束仍随成果继承，受约束内容不能扩大解释。例如“扫描覆盖完成”只复用覆盖结论，不推出“凭据已处置”；“本地启动通过”不推出“线上已发布”。

输入不一致、证据不可安全读取或范围不同：不得直接复用，输出STALE或无法安全复用及所需最小证据。不能以目录整体白名单、日期相近、相同工单名替代指纹。

## 责任边界

Codex只采集允许的事实、执行已授权增量、自测和PR；总控审批范围、影响扩散和门禁；项目所有者接受例外和永久风险；安全负责人及资产所有者处理秘密归属。工具只生成建议记录，不具有批准、风险降级、修复或基线生效权限。

门禁：1总控需求批准；2Codex提交材料；3总控批准合并；4本工单不适用；5双方验收、总控确认闭环。PASS是技术测试结果，不等于成果状态自动VERIFIED。
