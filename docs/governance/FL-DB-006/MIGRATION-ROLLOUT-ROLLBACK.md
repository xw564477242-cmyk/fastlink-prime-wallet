# 正式迁移、分批验证与fail-closed回滚设计

本文件仅为设计，无可执行SQL。本轮新增迁移0、执行SQL0、数据库/容器启动0。DB5三份隔离候选继续留在治理归档，禁止放回自动迁移目录；旧迁移不覆盖、不删除、不重排。

## 实施准入

先批准54表契约与身份来源，再另开业务实现工单。10仅Prisma模型和4仅历史目录表必须完成适用性对账；未解决对象保持BLOCKED。实际部署角色/GRANT仍未核验，本方案不授权连接。正式发布须独立门禁4、明确环境/回滚窗口/责任人，不能因设计PR合并自动应用。

## 策略与对象设计约束

- ACL与RLS分别给结论。启用RLS后没有策略会默认拒绝，但“拒绝全部”不是正向业务可用；普通runtime须非owner/无BYPASSRLS。owner只有独立迁移用途；按实际owner访问需求评估FORCE RLS，不能以FORCE覆盖superuser风险。
- SELECT限定主体/租户/环境及字段权限。INSERT验证新行归属与全部关联ID；UPDATE同时约束可见旧行和新行，且具备相应SELECT条件、列限制与状态转换。DELETE要批准业务语义，不默认允许删除资金记录。
- 多策略的OR/AND组合必须审计，避免某条宽策略绕过限定。NULL、继承、分区、FK/cascade、唯一约束错误和间接函数路径需单独验证；不把引用完整性内部检查当RLS覆盖。
- 租户条件不能代替列级限制；序列权限按需要授予，禁止通用PUBLIC授权。TRUNCATE等不受行策略保护的能力不给runtime；不写成本轮可执行清理步骤。
- 普通view需确认调用者安全语义与底层ACL/RLS；materialized view是独立缓存，刷新及读取角色、租户分片、过期数据需单独批准，不继承“底表安全”的结论。
- 函数优先调用者权限。必要definer函数固定安全search_path，排除可写schema的对象遮蔽，显式限定依赖，精确EXECUTE并审计PUBLIC默认执行及创建者默认权限。trigger与函数owner、调用链和任何动态对象名同审。
- 全量审查实际创建对象的每个owner的default privileges；显式记录为0不等于无默认授权。不扩大为本轮已查询运行数据库。

[PostgreSQL RLS](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)、[函数安全](https://www.postgresql.org/docs/17/sql-createfunction.html)、[默认权限](https://www.postgresql.org/docs/17/sql-alterdefaultprivileges.html)、[视图](https://www.postgresql.org/docs/17/sql-createview.html)是设计依据，不能替代本项目业务授权。

## 灰度与性能

后续先在批准的全新隔离库原样前向重建，再对代表升级状态测试增量。按依赖闭包分批而非随机抽表；每批正/反例、角色组合、锁等待/超时、执行计划和吞吐阈值由负责人预先批准。本轮不自行指定生产窗口或性能数值。长事务、池复用和任务交错必须加入负载条件。任一跨租户成功立即停止该对象扩展测试、固定脱敏证据，保持隔离；不得为了通过扩大授权。

## 失败关闭与两类回滚

未来运行回滚：停止受影响入口/任务与新票据签发，拒绝新业务请求，保留RLS/最小ACL和审计；已消费票据不复活、池中上下文不复用。兼容性失败不得回到可绕过RLS的旧应用。只允许退回已经证明兼容同等或更强权限边界的已批准版本；无法证明则保持服务不可用并另行审批。任何修复/反向迁移需独立、追加版本，不默认关闭RLS或恢复宽权限。

本治理交付回滚：如设计撤销，另开治理PR追加作废及替代说明，保留全部原文、SHA、旧FAIL/BLOCKED和审计链接。不得重置、强推、重写历史、恢复index/工作树登记、删除工具引用或证据、GC。没有SQL可以在本轮执行或回滚。
