# 风险分级、整改拆单及复验 R1
|编号|级别/状态|事实边界|独立工作及责任|
|---|---|---|---|
|DB-R02 / DB4-R01|潜在P0，未关闭|54业务表无RLS；继承DB1有DML角色跨租户历史FAIL；本轮新角色无DML|数据库负责人+安全负责人确认实际运行角色/GRANT/传播链，确定后端唯一入口或可信直连租户策略，再获批整改|
|DB4-R02|P0验收阻塞|原生无DML角色同租户也拒绝，缺少真实合法路径|资产所有者明确最小角色/对象/操作契约；未经批准不添加权限；重验同租户成功与跨租户拒绝|
|DB4-R03|P0重建前置|UAT第32步业务租户来源不明；本轮不重复失败|后端资金负责人批准独立seed来源及执行点，两轮空白重建后复核|
|DB4-R04|P1设计风险待确认|显式default ACL0，不证明未来函数PUBLIC EXECUTE受限|数据库负责人核对实际创建者、未来函数签名及最小EXECUTE，当前应用函数0|
|DB4-R05|BLOCKED|阶段B目标、部署JWT、客户端与实际服务角色未授权|项目所有者分别指定非生产目标、合成账号、安全注入及只读查询范围|

优先顺序：先确认角色和可达性，再选择最小权限/RLS整改模型；资金及外部链路继续关闭。DB3应用修复验收不能替代数据库策略。整改草案仅供审批，全部注释，不直接执行。
复验：将获批角色独立登录，验证membership/SET ROLE闭包、schema/table/default权限，再合法同租户和跨租户SELECT；首个跨租户成功停止该对象扩展。只有安全前提满足才继续合成INSERT/UPDATE/DELETE，核对目标摘要；覆盖依赖函数/视图/错误侧信道。不扩大到真实资金或外部供应商。
回滚：变更前记录经批准的ACL/策略和对象版本，未来独立PR回退相应变更；不得盲目恢复宽权限。当前没有整改可回滚，仅保留新任务容器和证据。
