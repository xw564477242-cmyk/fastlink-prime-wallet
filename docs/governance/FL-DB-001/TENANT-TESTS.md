# 双租户隔离验证

固定完全合成租户db001_tenant_a/b、客户db001_customer_a/b，无真实账号、客户资料或外部服务。两个新库初始化来自空白卷/空白数据库；插入夹具发生在原迁移执行结束或失败记录固化之后，没有用于绕过迁移前置条件。

共42用例：5种角色/库组合 × 同租户/跨租户 × SELECT/INSERT/UPDATE/DELETE =40，加2项tenant/user归属改写。每次显式BEGIN，结束ROLLBACK；SQL错误导致连接退出自动回滚。Tenant+Customer有序行集合SHA-256在每例前后相同，42/42不变。原始行内容不进入报告。

两项归属改写均影响1行后回滚。证明共享数据库角色或错误直连授权不能承载终端身份约束；不证明应用已经允许该输入。所有访问身份的current_user=session_user，superuser/BYPASSRLS/owns_customer均false；完整SQLSTATE/行数/哈希见evidence/tenant-probes.json。

未认证单独测试：不给密码的回环TCP连接被SCRAM拒绝。不是HTTP匿名请求验收。

复现方法：新隔离空白库、原样迁移、保留环境条件结果，创建仅限测试的最小角色和两组上述合成数据；按tenant/user归属构造SELECT、INSERT、UPDATE、DELETE及归属改写；以角色独立连接，在事务内读取行数，回滚，比较有序目标集合。绝不在正式库执行此流程。应用API应另用同一非特权后端连接、可信会话身份验证全部授权入口；当前未执行这部分。
