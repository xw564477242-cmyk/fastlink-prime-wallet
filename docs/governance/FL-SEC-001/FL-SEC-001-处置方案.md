# 凭据吊销、轮换、清理及复验方案

本文件仅为方案，所有动作均未执行。具体自然人和影响环境尚未确认，先由总控/安全负责人指定仓库负责人及系统凭据管理员；不得使用候选凭据验证。

|方案|适用项|责任与顺序|清理与复验|独立工单|
|---|---|---|---|---|
|P-URGENT|Critical完整私钥或助记词形态|安全负责人牵头，支付/银行/云平台管理员离线确认归属和权限；若疑似活跃生产凭据，启动紧急处置工单，按依赖和故障风险确定立即吊销或先替换再吊销|必要时同步证书/签名验证端、会话及派生凭据；审计滥用；经授权修复源码/制品后重扫；历史修复另行评审|是|
|P-ROTATE|High连接串/令牌/授权值等|系统负责人及安全管理员确认资产映射；新凭据最小权限配置、依赖切换、撤销旧凭据、审计使用记录，具体顺序须审批|源码仅引用秘密管理服务/环境变量；删除受影响构建缓存等须单独授权；以新工单验证旧凭据已禁用及扫描不再泄露|是，优先|
|P-REVIEW|Medium或未确认高熵候选|仓库负责人本地受限复核上下文，区分代码标识、完整性摘要、测试材料和真实凭据；明确所有者和环境后再决定轮换|保持现状与证据；未确认前不盲目吊销；确认秘密后转P-ROTATE或P-URGENT，误报需给出可复核依据|真实风险需另开|
|P-LOW|明确占位符、代码表达式、样例|仓库负责人保留误报依据，不进行凭据操作|未来规则调整后复验；不得将同路径所有内容整体加入白名单|一般无需|

每个非误报发现项通过索引plan字段关联本表，位置/指纹用于追踪。环境未知不等于测试环境；历史JWT过期也不自动证明可忽略，需评估签名密钥、刷新凭据和重用风险。

历史清理只在独立工单评估Lovable同步、协作副本、标签、制品及恢复要求后制定；本工单禁止历史重写、强推、GC或删分支。归档不得因含秘密而销毁，应先保全再按获批方案封存/脱敏。

密钥保留建议：门禁5前保留本地0600文件及0700父目录；验收后由总控决定继续受限保管或销毁。销毁会使后续扫描无法使用同一指纹体系，应先确认审计保留要求。此次不自动删除密钥或临时资产。
