# 处置顺序与责任

本工单仅形成方案，禁止实际认证、轮换、吊销、历史重写或生产变更。环境未知不能按测试环境处理。具体自然人由总控指定，索引已给出每项责任角色和优先级。

|优先级|适用|责任及具体下一步|后续清理与复验|
|---|---|---|---|
|P0|Critical|安全负责人及支付/云平台管理员立即受限确认资产归属、权限和依赖，另开紧急工单决定替换与吊销顺序|审计使用记录，获批切换后复验，历史清理单独评审|
|P1|High|安全负责人及受影响系统管理员按类型分组，先确认生产/支付/签名依赖，再按批准工单实施替换、切换、撤销与审计|以管理后台记录和脱敏扫描复验，不使用本次候选认证|
|P2|明确秘密字段、词形候选或配置/第一方中的Medium|仓库负责人及安全复核人依据内容SHA、偏移和私有定位链离线确认是否真实配置，关联具体系统和环境；确认真实风险后转P1/P0|保留证据，误报须写明结构依据；未确认前不自动轮换|
|P3|其他Medium|按历史→归档→依赖→缓存制品分组，结合完整性字段、签名、生成来源逐项复核；没有可证非秘密结构就保持风险候选|禁止整目录白名单；无需扩散原始内容，后续规则变更重新复验|
|P4|Low|仓库负责人保留逐项示例/非秘密结构证据，不执行凭据操作|规则回归时保留正反例，防止误降级|

每个非误报项均关联发现ID、不可逆指纹、来源层、内容SHA、定位信息、责任角色及处置优先级。High/Critical必须另开安全处置工单，Medium确认真实风险后同样另开。新旧HMAC迁移不触发凭据变化。
