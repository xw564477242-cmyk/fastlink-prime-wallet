# FL-GOV-001 分支规范与治理建议

本文件是治理规则与建议，不修改分支保护、CI 或运行行为；现存历史偏差不追溯改写。

## 长期分支及晋升

| 分支 | 职责 | 正常进入方式 |
| --- | --- | --- |
| dev | 日常集成、DEV 基线 | feature/* 经评审 PR |
| test | TEST 验证基线 | dev 经批准晋升 PR |
| uat | UAT 联调与验收 | test 经批准晋升 PR |
| main | 生产基线 | uat 经发布门禁晋升 PR |

唯一路径：feature/* → dev → test → uat → main；环境 DEV → TEST → UAT → 生产。禁止跨级合并、跨环境发布及直接向四个长期分支提交。本工单 PR 只允许以 dev 为 base；更高环境晋升另走工单与门禁。提交包含检查只能证明历史关系，不能替代部署环境证据和批准。

## 功能分支、提交及 PR

- 功能分支：feature/FL-工单号-简述；本工单 feature/FL-GOV-001-git-governance。可校验本工单全名，通用示例正则 `^feature/FL-[A-Z0-9]+(?:-[A-Z0-9]+)*-[a-z0-9]+(?:-[a-z0-9]+)*$`；工单真实性另核对工单系统。
- 提交：`[FL-XXX] 模块：简短描述`；本工单 `[FL-GOV-001] 治理：完成代码资产与分支基线盘点`。冒号为中文全角，禁止秘密值进入正文。
- PR 标题使用工单号及具体改动。描述关联工单，包含问题、范围、自测及未运行项、敏感扫描范围、风险、回滚和证据链接。
- Codex 负责开发、自测和 PR；ChatGPT 总控负责评审通过意见书。无意见书不得合并；本工单不得自动合并或部署。

## 五级门禁

1. 需求门禁：ChatGPT（总控）；标准化工单、优先级、范围与验收标准。
2. 提交门禁：Codex（执行）；PR、自测报告、改动说明、安全和范围检查。
3. 合并门禁：ChatGPT（总控）；代码评审通过意见书、测试通过、无敏感与越权变更。
4. 发布门禁：Codex（执行）；SHA、影响评估、发布及冒烟报告；本工单不部署。
5. 验收门禁：双方共同；验收报告、资产更新记录和文档同步后方可闭环。

## 推荐保护（尚未实施）

四长期分支建议禁止删除、强推和直接 push；PR 至少需总控批准，失效批准应重新审查，未解决讨论阻止合并。必需检查建议覆盖工单及目标分支、单元/静态检查、秘密扫描、diff 范围、环境晋升与制品 SHA。资金/状态机改动另需一致性校验，多租户改动另需跨租户隔离验收。应先核实当前规则及 CI 的实际检查名称，再单独批准实施，避免设置不存在的检查阻塞所有 PR。

原库已发布提交不 rebase/amend/squash/force push；Lovable 关联历史必须保留。合并方式应满足该历史保留要求；不得用 squash 清理已推送提交。

## 偏差处置顺序

1. P0：先保护脏工作区、游离 HEAD、缓存外提交与历史受阻 bundle；明确秘密安全保存及恢复方案。不得上传原始历史包。
2. P1：核定缺失的本地仓库映射，以及六库 uat、控制库 test 的适用性与正确基点。不能凭名称从任意提交补分支。
3. P1：对各长期分支独有提交逐项分类（业务/环境/合并），提出单独修复工单与验证方案，避免“统一”分支丢失资产。
4. P1：独立审批分支保护及必需检查；控制库和归档库的部署职责须先确认。
5. P2：增量采用分支/提交命名规范；清理失效工作树、删除旧分支或标签需单独工单，不能因为已合并或重复就自动删除。

## 紧急故障

必须记录故障原因、影响、例外范围、回补责任人和计划，48 小时内补齐正常流程。紧急标识不授权 Codex 自行生产变更；遵循实际工单授权。历史修复、默认分支变更、分支/标签删除和权限调整必须另开工单并审批。
