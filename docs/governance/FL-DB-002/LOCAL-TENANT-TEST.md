# 本机隔离双租户动态验证

## 环境与方法

验证于任务私有目录中执行。认证材料为本轮随机生成、仅适用于内存合成会话的值；父目录权限700、文件600，PR只记录不可逆SHA-256指纹和生命周期元数据。服务绑定 `127.0.0.1` 随机端口，执行后已停止。网络连接被限制为该回环端口，外部连接尝试数0。

加载后端固定HEAD中的原始 `TenantsController`、`AdminBearerGuard`、`TenantsService`和`AdminAuthService`，TypeScript仅在内存转译。没有导入AppModule，没有读取 `.env`，没有初始化Prisma客户端或连接数据库。持久层为严格合成Mock，仅接受预期Tenant谓词；因此结论是应用入口逻辑，不是数据库GRANT/RLS或已部署环境结论。

合成角色：租户A普通 `TENANT_ADMIN`，只有 `admin:read`，没有platform权限；另有租户B。两租户均为SANDBOX合成对象。

## 结果

| 用例 | 预期 | 实际 | 状态 |
|---|---:|---:|---|
| 未认证读取A | 401 | 401 | PASS |
| A管理员读取A | 200 | 200 | PASS |
| A管理员直接读取B | 403 | 403 | PASS |
| A管理员读取B，同时query声明 `tenantId=A` | 403 | 200且返回B | **FAIL** |

缺陷机制：守卫优先校验query/body `tenantId`，控制器和服务仍按路径 `:id` 查询对象，导致“授权检查对象”和“实际读取对象”不一致。首次确认外租户对象返回后，探针立即停止；扩展测试数0。未测试写入、更新、删除、列表、其他Admin路由或资金入口。

测试前后合成业务对象摘要一致；唯一允许的会话副作用是内存中的last-used触碰。没有真实数据、真实凭据、生产连接、供应商调用或数据库写入。

## 结论边界

`DB2-R01`定为确认P0应用层缺陷。它证明固定源HEAD的原始应用链在本机隔离条件下能够跨租户读取合成数据；不证明任何已部署版本包含该HEAD、路由可从公网到达、真实令牌可取得或生产数据已泄露。阶段B继续 `BLOCKED`；DB-R02真实部署暴露不得自动降级，也不得扩大为已确认生产事故。
