## 修复行为

- `pruneExpired()` 按 scope、lease 和请求 `isCurrent()` 清理失效条目；先从队列移除，再清除其去重窗口记录、释放 retry/controller 引用并中止在途重试。
- `report()` 在去重之前清理，并通知订阅者刷新；失效条目不再吞掉新请求同类错误。
- 发布队列快照时统一清理，关闭、页面释放及重试完成推进队列时跳过过期条目，保持其余有效异常 FIFO。
- 点击重试和关闭前也先清理，避免失效条目留下两秒去重记录。仍有效的异常继续遵守原显示/排队去重及两秒合并规则。
- 在途旧回调完成或失败时，因条目已移除而无法更新新提示或触发旧 401 失效处理。没有增加轮询或后台请求。

## 回归证据

保持同一页面 lease、不卸载组件，新增 6 个测试场景：

1. 请求换代 1 秒后同类错误重新报告：保留新 trace、新 id 和有效重试，新回调实际执行一次。
2. 评审复现的 5 秒场景：同上，不再保留旧 trace 或丢失重试按钮。
3. 旧请求重试在途时换代：旧 signal 被 abort、有效性回调为 false、旧 id 不再执行，延迟的 401 不影响新异常。
4. 关闭首项时跳过过期排队项，保留后续有效 FIFO，过期回调不可执行。
5. 页面 lease 释放推进队列时同样跳过过期项。
6. 首项重试成功推进队列时同样跳过过期项。

先加入测试、未修改实现时：原有 10 项通过，新增 6 项全部失败，独立复现缺陷。
修复后专项：16 pass、0 fail、76 assertions。
